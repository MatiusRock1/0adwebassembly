## Changes kept and their purpose

### Graphics bridge and transfer arena

- `source/renderer/backend/webgpu/Device.cpp` keeps binary commands and
  immutable snapshots of uniforms, vertices and indices. Opcode 12 adds
  buffer uploads to the same sequence, avoiding a synchronous `stageBuffer` for
  each upload. The CPU mirror keeps the neighbouring bytes when aligning writes.
- `wasm/browser/webgpu-engine.mjs` decodes the stream's words directly,
  avoids arrays and recursive dispatch per command, copies contiguous
  matrices and keeps the std140 paths with padding.
- It reuses uniform views, texture/storage groups and snapshots of
  blocks that did not change within the same submission. The epoch change
  invalidates snapshots on submit. Retiring resources invalidates the groups.
- A reusable `COPY_SRC` arena keeps each upload in its original order
  between draws. It is written before submitting the command buffer; a range of an
  earlier upload within that submission is not overwritten.

### New asynchronous queue: compiled, pending execution

- `source/renderer/backend/webgpu/CommandQueue.h` is the production
  implementation. It copies strings and bytes; it only frees calls confirmed through
  an atomic. It limits pending calls and bytes; a single upload larger
  than the budget is consumed before allowing another call.
- `Device.cpp` enqueues `commands`, `present` and `release` through
  `MAIN_THREAD_ASYNC_EM_ASM`. Each synchronous call first drains the queue to
  keep resource dependencies. Idle and destruction also wait.
- The sequence is checked in JavaScript; an order change fails
  explicitly. The goal is to overlap the next update with the encoding
  of the previous frame, keeping data and order. **Its real effect is still unknown.**
- `phase4-application-patch.py` changes the frame observer of the prepared copy
  of `main.cpp` to asynchronous submission, to avoid that observer forcing a wait
  per frame. The original `source/main.cpp` was not edited for this.
- `phase4-5-engine-build.py` includes `CommandQueue.h` in the build identity.
  `Device.cpp` and `main.cpp` compiled; the later link ended with exit code 0.

### Clock and VM

- The clock uses monotonic elapsed time and keeps the time of long
  frames. Do not go back to the inverse of filtered FPS: it lost simulated time.
- The `TurnManager` catch-up cap, the original speed,
  Petra, the components or the scripts were not changed to hide the cost.
- `portable-fixed-o3` uses SpiderMonkey 128.13.0, the official Portable Baseline
  interpreter, with `PortableBaselineInterpret.o` at O3. It keeps the maths options
  and the verified public headers. There is no native JIT in WASM.
- The only backport is the enum assignment of Mozilla D224659 in a private
  copy of the VM. Patch and provenance are in `wasm/patches/upstream`.
  Compiling it **does not prove** that it fixes the real combat failure.
- Docker keeps the case-sensitive Linux volume
  `0ad-phase45-spidermonkey-portable`; it is needed because of `String.h`/`string.h`.
  Do not rebuild SpiderMonkey on NTFS nor overwrite the original cache.
